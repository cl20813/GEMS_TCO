AMAREL VECCHIA GPU / OPTIMIZATION 설정 메모
갱신: 2026-09-03

[현재 권장 구성]

- 비교 방법: adapted vs fixed (union 제외)
- 공간 block: 4x4, block당 최대 16 points
- lag 구조: 6/4/3
- fitting batch: target_chunk_size=256
- torch.float64, Matern smooth=0.5
- Amarel 한 node / 한 task / GPU 1개 / 날짜별 순차 실행
- float64 Cholesky/solve가 중심이므로 L40S보다 A100 우선

[GPU batch size의 두 단위]

- 과거 개별(point-target) Vecchia 최적 batch: 약 4,800 target rows
- 4x4 block Vecchia의 target_chunk_size는 point 수가 아니라 block 수
- 64 blocks = 최대 1,024 target points
- 128 blocks = 최대 2,048 target points
- 256 blocks = 최대 4,096 target points
- 512 blocks = 최대 8,192 target points
- 따라서 256이 과거 pointwise 4,800과 가장 가까운 실질 작업량
- pointwise 값 4,800을 block chunk에 직접 넣으면 안 됨

[A / AB / ABC 구조]

- block은 centroid max-min ordering으로 정렬
- 같은 시간대에서는 현재 block보다 ordering상 앞선 block만 conditioning 가능
- A: 현재 t에서 이전 spatial block 최대 6개
- B: t-1 corridor에서 4개
- C: t-2 corridor에서 3개
- A batch: A6 = conditioning 최대 96 points; target 포함 행렬 최대 112x112
- AB batch: A6+B4 = 최대 160 points; target 포함 최대 176x176
- ABC batch: A6+B4+C3 = 최대 208 points; target 포함 최대 224x224
- adapted: 보정된 signed 2-D advection corridor로 graph 생성
- fixed: 고정 reference/target-centered corridor로 graph 생성
- conditioning graph는 fitting 전에 한 번 만들고 LBFGS 중에는 재생성하지 않음

[다음 production용 LBFGS 권장값]

lr=1.0
line_search_fn="strong_wolfe"
max_iter=20
max_eval=20
history_size=40
tolerance_grad=1e-5
tolerance_change=1e-9
outer max_steps=5
outer grad_tol=1e-5

- 실제 outer loop은 2024-07-03 benchmark에서 2회 수렴
- 그래도 outer max_steps는 2로 자르지 말고 안전 상한 5 유지
- strong_wolfe 때문에 outer step 1회 안에서도 closure/NLL 평가가 여러 번 발생
- positive covariance parameter는 log scale에서 최적화
- GLS beta는 likelihood 안에서 계산

중요: 위 batch benchmark는 history_size=10으로 측정됨.
history_size=40은 다음 production 실행용 제안이며 아직 10과 직접 비교하지 않음.
parameter가 7개라 history 자체의 GPU 부담은 작을 것으로 예상되지만,
재현성을 위해 run_config.json에 실제 값을 반드시 기록할 것.
